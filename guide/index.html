WHAT · 무엇을 만드나

Ubuntu 보안 취약점·패치 관리 DB 시스템

Ubuntu 24.04 서버에 깔린 Apache, OpenSSH의 보안 취약점(CVE)과 위험도(CVSS), Ubuntu 패키지별 수정 상태를 DB에 넣고, 서버별로 누가 · 언제까지 · 어떤 상태로 조치하고 있는지 관리합니다.

CVE와 패치 정보는 실제 데이터(10~15건), 서버·담당자·조치 이력은 가상 데이터를 씁니다.

이것만은 기억하기

  • 메인은 DB 설계와 SQL이에요. Python은 그걸 보여주는 도구고요.
  • LLM은 시간이 남을 때 붙이는 추가 기능이에요. LLM 없이도 시연이 다 돼야 합니다.
  • 기존 보안 도구(Wazuh, Trivy 등)를 대체하려는 게 아니에요. 자동 스캔이나 자동 패치는 안 만듭니다.

SCHEMA · 테이블 초안 (11/23 확정 예정)

테이블뭘 저장하나키데이터수업 예제로 치면
softwareApache, OpenSSH + Ubuntu 소스 패키지명software_id실제10주차 products처럼 기준이 되는 목록
vulnerabilitiesCVE 번호, 설명, CVSS 점수·버전·벡터·출처, Ubuntu prioritycve_id실제1주차 PK 조건(유일·NOT NULL·불변)을 만족하는 CVE 번호를 id 대신 그대로 PK로 씀
cve_package_statusUbuntu 릴리스·패키지별 영향 상태, 수정 버전, USN(cve_id, software_id, ubuntu_release)실제CVE ↔ 소프트웨어 N:M 중간 테이블 + 릴리스별 속성(상태·수정 버전). 복합 PK 3개 컬럼
systems서버 호스트명, Ubuntu 버전, 환경(prod/dev)system_id가상6주차 users처럼 서버 한 대 = 행 하나
installed_software서버별 설치 패키지와 버전(system_id, software_id)가상10주차 order_details / 6주차 likes 같은 N:M 중간 테이블 (서버 ↔ 소프트웨어 + 설치 버전)
staff조치 담당자staff_id가상6주차 users
system_vulnerabilities서버별 조치 건: 상태, 담당자, 기한, 완료일sv_id, UNIQUE(system_id, cve_id)가상6주차 appointments(의사-환자 N:M + 날짜 속성)처럼 서버-CVE N:M + 상태·담당자·기한
patch_history상태 변경 이력 (트리거가 자동 기록)history_id가상조치 건 1개에 여러 행이 쌓이는 1:N 기록 (10주차 orders → payments 관계와 같은 모양)

수업 언어로 읽는 제약조건

  • UNIQUE(system_id, cve_id) = 6주차 likes에서 같은 사람이 같은 사진에 좋아요를 두 번 넣는 문제를 막는 장치예요. 같은 서버에 같은 CVE 조치 건은 1개만.
  • assignee_id가 NULL = 6주차 photos.user_id IS NULL처럼 "가리키는 대상(담당자)이 아직 없음". 12주차 ERD로는 선택적 관계(원 표시)예요.

복합 PK가 뭔가요?

컬럼 2~3개를 묶어서 "이 조합은 한 번만 나온다"를 PK로 삼는 거예요. 수업 예제는 항상 id INTEGER AUTO_INCREMENT 하나였지만, installed_software는 (서버, 소프트웨어) 조합 자체가 행을 구분하니까 따로 id를 만들지 않았어요. 같은 서버에 같은 소프트웨어가 두 번 들어가는 것도 PK가 막아 줘요.

VALUES · 상태값 (모두 이 값만 쓰기)

Ubuntu 패키지 상태

cve_package_status.status

  • released 수정 패키지가 나옴 (fixed_version 필수)
  • needed 영향 있음, 아직 수정 안 됨
  • not-affected 영향 없음
  • deferred / ignored 보류·무시

서버별 조치 상태

system_vulnerabilities.status

  • open 확인됨, 아직 착수 안 함
  • in_progress 조치 중
  • patched 패치 완료 (patched_at 필수)
  • risk_accepted 위험 수용 (조치 안 하기로 결정)

DICT · 수업에 없던 문법 미니 사전

강의자료(1~7, 10~12주차)에 없던 것만 모았어요. 오른쪽 예는 모두 우리 db/schema.sql·seed.sql·README.md·docker-compose.yml에 실제로 있는 코드예요.

문법한 줄 설명우리 코드 속 실제 예
CHECK값이 조건을 만족해야 저장돼요 (MySQL 8.0.16부터 실제로 검사)CHECK (cvss_score IS NULL OR cvss_score BETWEEN 0.0 AND 10.0) → 11.0을 넣으면 오류 3819
TRIGGER표에 INSERT/UPDATE가 일어나면 자동으로 실행되는 SQLtrg_sv_after_update: OLD.status <> NEW.status이면 patch_history에 (이전 상태, 새 상태, NEW.updated_by) INSERT
VIEW자주 쓰는 SELECT에 이름을 붙여 표처럼 조회v_open_risks = 미해결 조치 건 + 서버·CVE·담당자 JOIN → SELECT * FROM v_open_risks;
IF() / CASE조건에 따라 다른 값. IF는 두 갈래, CASE는 여러 갈래IF(sv.due_date IS NOT NULL AND sv.due_date < CURDATE(), 1, 0) AS is_overdue (v_open_risks). CASE 예는 ② 페이지
COALESCE(a, b)a가 NULL이면 bCOALESCE(SUM(sv.status = 'patched'), 0) — 조치 건 0개 서버는 SUM이 NULL이라 0으로
NULLIF(a, b)a와 b가 같으면 NULL… / NULLIF(COUNT(sv.sv_id), 0) — 0으로 나누는 대신 완료율을 NULL로
SUM(조건식)MySQL에서 조건은 참=1, 거짓=0이라 더하면 개수가 돼요SUM(sv.status = 'patched') = patched 건수 (v_system_patch_rate)
트랜잭션
COMMIT / ROLLBACK		여러 문장을 한 묶음으로: 다 반영(COMMIT)하거나 다 취소(ROLLBACK)seed.sql은 START TRANSACTION; … COMMIT;, 테스트와 채점기는 끝에 ROLLBACK해서 데이터를 안 바꿔요
복합 PK컬럼 여러 개의 조합이 유일PRIMARY KEY (system_id, software_id) (installed_software)
복합 FK컬럼 여러 개를 한꺼번에 다른 표의 PK로 참조FOREIGN KEY (system_id, software_id) REFERENCES installed_software (system_id, software_id) — 설치 안 된 소프트웨어의 취약점은 오류 1452
ON DELETE RESTRICT / CASCADE부모 행을 지울 때 자식이 있으면 막기 / 자식도 같이 지우기조치 건이 있는 담당자 삭제는 RESTRICT라 오류 1451. 조치 건을 지우면 patch_history는 CASCADE로 같이 지워져요
REGEXP_LIKE문자열이 패턴(정규식)에 맞는지 검사CHECK (REGEXP_LIKE(cve_id, '^CVE-[0-9]{4}-[0-9]{4,}$', 'c')) — 'c'는 대소문자 구분
Docker모두 똑같은 MySQL을 한 줄로 띄우는 실행 환경docker-compose.yml: image: mysql:8.0, ports: "${MYSQL_PORT:-3306}:3306"
Git파일 변경 이력 관리 + 공동 작업feature/역할-작업명 브랜치 → PR → main (GitHub 페이지)
pymysqlPython에서 MySQL에 접속하는 라이브러리. autocommit이 꺼져 있어서 바꾼 뒤 conn.commit()이 필요해요pymysql.connect(host="127.0.0.1", port=3306, user="vuln_app", password="...", database="vuln_mgmt", charset="utf8mb4") (README)
파라미터 바인딩 %sSQL에는 값 자리만 두고 값은 따로 넘겨요. 문자열을 이어 붙이지 않아 SQL Injection을 막아요UPDATE system_vulnerabilities SET status = 'patched', patched_at = NOW(), updated_by = %s WHERE sv_id = %s; (README 규칙 1)
