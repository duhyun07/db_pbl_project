문제 1

실제 CVE 1건 적재: DB 값 = 원본 JSON 값

담당 ④ 체크리스트 선행 #0

PROBLEM · 문제

새로 나온 OpenSSH 취약점 1건을 NVD·Ubuntu에서 받아 vulnerabilities, cve_package_status에 넣고, DB 값이 원본 JSON과 같은지 확인한다.

CHECKLIST · 확인 항목 (체크하면 이 브라우저에 저장돼요)

NOTE · 노트

  • Ubuntu JSON의 noble을 그대로 넣으면 CHECK 오류 3819가 나요. DB에는 24.04.
  • CVSS가 없으면 NULL. 0점은 "안전"으로 오해돼요.

HINT · 힌트 (관련 수업)

정답 대신 다시 볼 수업 주차예요. 수업에 없던 문법은 공통 가이드의 미니 사전에 있어요.

  • 5주차 자료형 (DECIMAL, DATE, ENUM)
  • 1주차 PK 조건

JUDGE · 채점 방법

체크리스트 문제라 맞음/틀림을 매기지 않아요. 위 항목을 직접 확인하고 체크하세요.

python judge/judge.py 1

RESET · 이 단계 시작 상태로 되돌리기

실제 데이터 적재 전 상태: schema.sql만 다시 실행 (seed는 넣지 않음)

# Docker (레포 루트, 기존 데이터는 모두 지워져요)
docker compose exec db sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 < /work/db/schema.sql && mysql -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 < /work/db/seed.sql'
