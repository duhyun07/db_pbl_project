문제 5 · 초안

기한을 넘긴 미해결 조치 건

담당 ② 채점 초안 · 11/23 회의에서 확정 선행 #0

PROBLEM · 문제

기준일이 주어졌을 때, 조치 기한(due_date)이 기준일보다 이전이고 status가 open 또는 in_progress인 조치 건을 찾는다. 기한이 NULL이면 기한 초과가 아니다.

IO · 입력과 출력

입력

sql/q05.sql: SELECT 문 1개. 파라미터 1개 %s = 기준일 (예: '2026-11-25').

출력

hostname, cve_id, due_date. due_date 오름차순, 같으면 hostname 오름차순.

LIMIT · 제한

  • CURDATE()/NOW() 금지 — 기준일은 파라미터로만
  • %s 파라미터 사용

EXAMPLE · 예제

예제 1

파라미터: base_date = 2026-11-25

예제 입력 (필요한 컬럼만)

systems

system_idhostname
1web-01
2web-02

system_vulnerabilities

이 밖에 숨은 케이스가 3개 있어요. 숨은 케이스가 틀리면 입력은 보여 주지 않고 "숨은 케이스 n"이라고만 나와요.

NOTE · 노트

  • sv 2는 기한이 지났지만 patched라서 빠져요.
  • sv 4는 기한이 NULL이라 기한 초과가 아니에요.
  • sv 5는 risk_accepted(위험 수용)라 미해결이 아니에요. status <> 'patched'로 쓰면 여기서 틀려요.
  • 기한이 기준일과 같은 날이면 아직 초과가 아니에요 (보다 "이전").

HINT · 힌트 (관련 수업)

정답 대신 다시 볼 수업 주차예요. 수업에 없던 문법은 공통 가이드의 미니 사전에 있어요.

  • 3주차 WHERE·AND/OR
  • 4주차 IN
  • 5주차 DATE
  • 7주차 JOIN
  • 10주차 ORDER BY

JUDGE · 채점 방법

제출 파일 sql/q05.sql을 만든 뒤 실행해요. 맞았습니다!!가 나오면 다음 문제로 넘어가요. 채점기는 케이스마다 ROLLBACK해서 DB를 바꾸지 않아요.

# vuln-mgmt 레포 루트에서
python judge/judge.py 5

RESET · 이 단계 시작 상태로 되돌리기

채점기는 케이스마다 ROLLBACK해서 DB를 바꾸지 않아요. 직접 실험하다 데이터가 바뀌었으면 schema·seed 다시 적재 (공통 가이드의 명령, Plan B는 Workbench에서 schema.sql → seed.sql 실행)

# Docker (레포 루트, 기존 데이터는 모두 지워져요)
docker compose exec db sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 < /work/db/schema.sql && mysql -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 < /work/db/seed.sql'

# Plan B (수업용 MySQL): Workbench에서 db/schema.sql 열고 실행(⚡) → db/seed.sql 열고 실행(⚡)
