문제 3

조치 건 등록과 무결성 (실패해야 정답)

담당 ①④ 실패해야 정답 선행 #0

PROBLEM · 문제

영향받는 서버에 조치 건을 등록하는 INSERT와, CVE를 등록하는 INSERT를 작성한다. 정상 데이터는 들어가야 하고, 잘못된 데이터는 DB 제약조건이 막아야 한다. 막혔을 때 나오는 MySQL 오류 코드가 채점 기준이다.

IO · 입력과 출력

입력

제출 파일 2개.
sql/q03_register.sql: system_vulnerabilities에 1행 INSERT. 파라미터 8개를 이 순서로 %s: system_id, cve_id, software_id, status, assignee_id, due_date, patched_at, updated_by
sql/q03_cve.sql: vulnerabilities에 1행 INSERT. 파라미터 3개를 이 순서로 %s: cve_id, description, cvss_score

출력

케이스마다 "성공" 또는 MySQL 오류 코드. 성공하면 채점기가 등록된 행과 patch_history를 확인한다.

LIMIT · 제한

  • 값을 SQL에 직접 쓰지 말고 %s 파라미터만 사용
  • 한 파일에 SQL 문장 하나

이 밖에 숨은 케이스가 3개 있어요. 숨은 케이스가 틀리면 입력은 보여 주지 않고 "숨은 케이스 n"이라고만 나와요.

NOTE · 노트

  • dev-01에는 OpenSSH(software_id 2)만 설치돼 있어요. Apache 취약점은 등록할 수 없어야 해요 (복합 FK).
  • 같은 서버에 같은 CVE를 두 번 등록하면 안 돼요. 6주차 likes 중복 좋아요 문제와 같은 상황이에요.
  • patched인데 완료 시각이 없으면 CHECK가 막아요.
  • cve-0000-0004처럼 소문자로 써도 막혀야 해요. 이 DB는 대소문자를 구분하지 않는 콜레이션이지만 CHECK는 구분해요.

HINT · 힌트 (관련 수업)

정답 대신 다시 볼 수업 주차예요. 수업에 없던 문법은 공통 가이드의 미니 사전에 있어요.

  • 1주차 PK 조건(유일)
  • 6주차 FK·NOT NULL
  • 12주차 이상 현상

JUDGE · 채점 방법

제출 파일 sql/q03_register.sql, sql/q03_cve.sql을 만든 뒤 실행해요. 맞았습니다!!가 나오면 다음 문제로 넘어가요. 채점기는 케이스마다 ROLLBACK해서 DB를 바꾸지 않아요.

# vuln-mgmt 레포 루트에서
python judge/judge.py 3

RESET · 이 단계 시작 상태로 되돌리기

채점기는 케이스마다 ROLLBACK해서 DB를 바꾸지 않아요. 직접 실험하다 데이터가 바뀌었으면 schema·seed 다시 적재 (공통 가이드의 명령, Plan B는 Workbench에서 schema.sql → seed.sql 실행)

# Docker (레포 루트, 기존 데이터는 모두 지워져요)
docker compose exec db sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 < /work/db/schema.sql && mysql -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 < /work/db/seed.sql'

# Plan B (수업용 MySQL): Workbench에서 db/schema.sql 열고 실행(⚡) → db/seed.sql 열고 실행(⚡)
