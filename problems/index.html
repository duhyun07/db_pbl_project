PROBLEMS · 단계별로 풀고 채점하기

문제

구현 단계마다 정해진 입력 → 기대 결과와 비교 → 맞으면 다음 단계로 가요. 문제 번호 순서가 곧 발표 시연 순서예요. 앞 문제 결과 위에 쌓이니까 "선행" 문제를 먼저 풀어 주세요.

SCENARIO · 시연 순서

새 OpenSSH 취약점 등장 (#1) → 영향받는 서버 (#2) → 조치 건 등록·담당자 배정 (#3) → 조치와 이력 (#4) → 기한 초과 (#5) → 완료율 (#6, #7) → 화면 (#8) → 성능 (#9)

HOW · 채점하는 법

실행

# vuln-mgmt 레포 루트에서 (처음 한 번)
pip install -r judge/requirements.txt

python judge/judge.py --list    # 문제 목록
python judge/judge.py 5         # 5번 채점
python judge/judge.py --all     # 전체

접속 정보는 .env를 읽어요. Docker가 안 되는 Plan B(수업용 MySQL)에서도 .env의 포트·계정만 맞추면 돌아가요.

RULE · 제출 규칙

  • 제출 파일은 vuln-mgmt의 sql/qNN.sql. 파일 하나에 SQL 문장 하나. ③이 쓰는 sql/query_catalog.json의 SQL과 같은 문장이어야 해요.
  • 값은 SQL에 직접 쓰지 않고 %s(또는 %(이름)s) 파라미터로. 파라미터가 있는 SQL에서 % 글자가 필요하면 %%.
  • 기준일이 필요한 문제는 CURDATE() 대신 파라미터를 써요. seed 날짜가 오늘 기준이라 결과가 날마다 바뀌는 걸 막기 위해서예요.
  • 문제를 통과시키려고 judge/problems/의 케이스를 고치지 않아요. 기대 결과가 이상하면 팀장에게 알려 주세요.
