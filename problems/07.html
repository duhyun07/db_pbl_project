문제 7 · 초안

평균보다 미해결이 많은 서버 (HAVING + 서브쿼리)

담당 ② 채점 초안 · 11/23 회의에서 확정 선행 #6

PROBLEM · 문제

서버별 미해결(open, in_progress) 조치 건수를 구하고, 그 건수가 "모든 서버의 미해결 건수 평균"보다 많은 서버를 찾는다. 평균에는 미해결이 0건인 서버도 포함한다.

IO · 입력과 출력

입력

sql/q07.sql: SELECT 문 1개. 파라미터 없음.

출력

hostname, unresolved_count. unresolved_count 내림차순, 같으면 hostname 오름차순.

LIMIT · 제한

  • 평균은 서브쿼리로 계산 (숫자를 직접 쓰지 않기)

EXAMPLE · 예제

예제 출력

web-013

이 밖에 숨은 케이스가 2개 있어요. 숨은 케이스가 틀리면 입력은 보여 주지 않고 "숨은 케이스 n"이라고만 나와요.

NOTE · 노트

  • 예제: web-01 3, web-02 1, db-01 1, dev-01 0 → 평균 5/4 = 1.25 → web-01만.
  • 0건 서버를 빼고 평균을 내면(5/3) 숨은 케이스에서 틀려요. 서버 목록은 systems에서 시작해야 해요.
  • patched, risk_accepted는 미해결이 아니에요.

HINT · 힌트 (관련 수업)

정답 대신 다시 볼 수업 주차예요. 수업에 없던 문법은 공통 가이드의 미니 사전에 있어요.

  • 10주차 GROUP BY·HAVING
  • 11주차 FROM절·HAVING절 서브쿼리
  • 7주차 LEFT JOIN

JUDGE · 채점 방법

제출 파일 sql/q07.sql을 만든 뒤 실행해요. 맞았습니다!!가 나오면 다음 문제로 넘어가요. 채점기는 케이스마다 ROLLBACK해서 DB를 바꾸지 않아요.

# vuln-mgmt 레포 루트에서
python judge/judge.py 7

RESET · 이 단계 시작 상태로 되돌리기

채점기는 케이스마다 ROLLBACK해서 DB를 바꾸지 않아요. 직접 실험하다 데이터가 바뀌었으면 schema·seed 다시 적재 (공통 가이드의 명령, Plan B는 Workbench에서 schema.sql → seed.sql 실행)

# Docker (레포 루트, 기존 데이터는 모두 지워져요)
docker compose exec db sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 < /work/db/schema.sql && mysql -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 < /work/db/seed.sql'
