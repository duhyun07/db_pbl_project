문제 2

가상 서버·설치 패키지 생성 (seed 고정 시 개수 일치)

담당 ④ 채점 (DB 상태 검사) 선행 #0, #1

PROBLEM · 문제

python data/generate_synthetic.py --mode demo로 시연용 서버 6대와 설치 패키지를 만든다. random seed를 고정했으므로 누가 실행해도 아래 개수가 정확히 나와야 한다.

IO · 입력과 출력

입력

없음. 실제 데이터(software, vulnerabilities, cve_package_status)를 적재한 DB에서 생성기를 실행한 뒤 채점한다.

출력

채점기가 아래 확인 쿼리를 실행해 기대값과 비교한다.

LIMIT · 제한

  • 설치 버전(installed_version)은 지어내지 않고 cve_package_status.fixed_version에 있는 값 중에서 고른다.
  • ubuntu_release는 코드명이 아니라 24.04.

CHECK · 채점기가 확인하는 것

확인쿼리기대값
1. 서버 6대SELECT COUNT(*) FROM systems6
2. 서버 이름SELECT hostname FROM systemsweb-prod-01 / web-prod-02 / web-stg-01 / db-prod-01 / dev-01 / dev-02
3. 환경별 대수SELECT CAST(environment AS CHAR), COUNT(*) FROM systems GROUP BY environmentprod, 3 / staging, 1 / dev, 2
4. 모든 서버 24.04SELECT COUNT(*) FROM systems WHERE ubuntu_release <> '24.04'0
5. 소프트웨어별 설치 서버 수SELECT s.source_package, COUNT(*) FROM installed_software i JOIN software s ON s.software_id = i.software_id GROUP BY s.source_packageapache2, 4 / openssh, 6
6. 설치 버전이 실제 수정 버전 중 하나SELECT COUNT(*) FROM installed_software i WHERE NOT EXISTS (SELECT 1 FROM cve_package_status c WHERE c.software_id = i.software_id AND c.fixed_version = i.installed_version)0
7. 담당자 4명SELECT COUNT(*) FROM staff4

NOTE · 노트

  • "설치 버전이 실제 수정 버전 중 하나"가 0이 아니면 버전을 지어낸 거예요.
  • 환경별 대수: prod 3, staging 1, dev 2. 서버 이름까지 맞아야 ③의 시연 시나리오가 그대로 동작해요.

HINT · 힌트 (관련 수업)

정답 대신 다시 볼 수업 주차예요. 수업에 없던 문법은 공통 가이드의 미니 사전에 있어요.

  • 6주차 FK·N:M 중간 테이블
  • 4주차 COUNT
  • 10주차 GROUP BY
  • 11주차 NOT EXISTS

JUDGE · 채점 방법

생성기를 실행한 뒤 채점기를 실행해요. 맞았습니다!!가 나오면 다음 문제로 넘어가요. 채점기는 케이스마다 ROLLBACK해서 DB를 바꾸지 않아요.
