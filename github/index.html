WINDOWS · 2번 설치 자세히

Git 설치

  1. git-scm.com/downloads → Windows → 64-bit 설치 파일 받기
  2. 설치 화면은 대부분 기본값 그대로 Next. 편집기 선택 화면에서는 VS Code를 골라도 돼요.
  3. "Adjusting your PATH environment" 화면은 기본값(Git from the command line and also from 3rd-party software)을 그대로 두세요. 그래야 PowerShell에서 git 명령이 돼요.
  4. 설치가 끝나면 PowerShell을 새로 열고 확인해요.
git --version
git version 2.xx.x.windows.1

숫자는 설치한 버전에 따라 달라요. git version으로 시작하면 성공이에요.

Docker Desktop 설치 (WSL 2)

Windows의 Docker Desktop은 WSL 2 설치와 재부팅이 필요해요. 처음이면 30분 이상 걸릴 수 있으니 시간 여유가 있을 때 하세요. 하루 안에 안 되면 아래 Plan B로 먼저 작업을 시작해요.
  1. WSL 2 먼저: 시작 메뉴에서 PowerShell을 관리자 권한으로 실행 → wsl --install → 끝나면 재부팅
  2. Docker Desktop 설치 파일 실행 → "Use WSL 2 instead of Hyper-V" 체크를 그대로 두고 설치
  3. 설치 후 Docker Desktop을 실행하고, 엔진이 실행 중(Engine running)이 될 때까지 기다리기. 처음엔 약관 동의·로그인 화면이 나오는데 로그인은 건너뛰어도 돼요.
  4. PowerShell을 새로 열고 확인해요.
# WSL 확인 (기본 버전이 2인지)
wsl --status

# Docker 확인
docker --version
docker compose version
docker run hello-world

docker run hello-world 출력에 Hello from Docker!가 보이면 성공이에요. Docker Desktop은 MySQL을 쓰는 동안 항상 켜 둬야 해요.

PLAN B · Docker가 안 될 때 (수업용 MySQL)

1. 버전 확인

수업용 MySQL이 8.0.16 이상이어야 CHECK 제약조건이 실제로 동작해요. 그보다 낮으면 잘못된 값이 그냥 들어가서 문제 #3이 틀려요.

SELECT VERSION();
8.0.46   ← 8.0.16 이상이면 OK (숫자는 PC마다 달라요)

2. 스키마·seed 적재

  1. Workbench에서 수업용 연결(root)로 접속
  2. File → Open SQL Script → vuln-mgmt의 db/schema.sql → 번개(⚡) 버튼으로 전체 실행
  3. 같은 방법으로 db/seed.sql 실행
  4. USE vuln_mgmt; SHOW TABLES; → 10행이면 성공

Safe Updates 모드가 켜져 있어도 두 파일은 끝까지 실행돼요 (확인함). 다시 처음 상태로 만들 때도 이 순서로 다시 실행해요.

3. .env 맞추기

# Plan B용 .env (수업용 MySQL 계정으로)
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=수업에서 쓰는 root 비밀번호
MYSQL_DATABASE=vuln_mgmt

이렇게 맞추면 채점기(python judge/judge.py)와 ③의 앱도 그대로 돌아가요.

Plan B에서 안 되는 것

  • docker compose … 명령과 tests/run_tests.sh (Docker 안의 mysql을 쓰기 때문). 무결성 확인은 문제 #3 채점으로 대신해요.
  • 팀원마다 MySQL 버전이 다를 수 있어요. 결과가 이상하면 SELECT VERSION(); 결과를 단톡에 같이 올려 주세요.

RULES · 같이 쓰는 규칙

브랜치 이름

feature/역할-작업명 형식으로 지어요.

①feature/db-trigger
②feature/sql-performance
③feature/app-search
④feature/data-collect
버그fix/app-status-update

커밋 메시지

영역: 무엇을 했는지 한 줄이면 충분해요.

  • db: patch_history 자동 기록 트리거 추가
  • sql: 기한 초과 미해결 건 쿼리 추가
  • app: 패치 상태 변경 화면
  • data: NVD 수집 스크립트
  • docs: 데이터 매핑 문서

PR 규칙

  • main에 직접 push하지 않고 항상 PR로 합치기
  • PR 설명에 무엇을 바꿨는지, 어떻게 확인했는지 2~3줄
  • 다른 한 명이 확인하고 Merge (급하면 단톡에 말하고 본인 Merge)
  • PR은 작게. 하루 작업을 하루 안에 합치기
  • db/schema.sql을 건드리는 PR은 반드시 ①이 확인

하지 말 것

  • git add . — 다른 파일까지 같이 올라가요
  • git push --force — 다른 사람 작업이 날아가요
  • .env, 비밀번호, API 키 커밋
  • 남의 폴더 파일 마음대로 수정 (필요하면 담당자에게 말하기)
  • 며칠씩 PR 안 하고 혼자 쌓아 두기 (나중에 충돌 지옥)

CONFLICT · 충돌이 났을 때

main의 최신 내용을 내 브랜치에 반영

git switch main
git pull
git switch feature/내-브랜치
git merge main

충돌 난 파일을 열면 <<<<<<< ~ >>>>>>> 사이에 두 버전이 보여요. 남길 내용만 남기고 표시를 지운 뒤:

git add 충돌난파일
git commit
git push

모르겠으면 멈추고 공유

충돌이 다른 사람 파일에서 났거나, 뭘 남겨야 할지 모르겠으면 아무것도 지우지 말고 단톡에 git status 결과를 캡처해서 올려 주세요.

Git은 커밋만 해 두면 거의 다 되돌릴 수 있어요. 무서운 건 커밋 안 한 작업을 날리는 거예요.

VS Code를 쓰면 충돌 부분에 "Accept Current / Incoming / Both" 버튼이 떠서 훨씬 쉬워요.
