05 · 모두 한 번씩 따라 하기

GitHub 세팅·공동 작업

처음 한 번만 하는 세팅과, 매일 반복하는 작업 흐름을 정리했어요. Git이 익숙하지 않아도 위에서부터 순서대로 따라 하면 됩니다.

SETUP · 처음 한 번만 (팀원)

3 · 4 · 5 명령어

# 3. 사용자 정보 (GitHub 이메일과 같게)
git config --global user.name "홍길동"
git config --global user.email "you@example.com"

# 4. clone
git clone https://github.com/duhyun07/db_pbl_project.git
cd db_pbl_project

# 5. 환경 변수 파일 (Windows는 copy)
cp .env.example .env

6 · MySQL 실행

# DB 켜기 (처음엔 이미지 받느라 조금 걸려요)
docker compose up -d

# 접속 확인
docker compose exec db mysql -u root -p vuln_mgmt
mysql> SHOW TABLES;

# 스키마를 처음부터 다시 만들고 싶을 때
docker compose down -v
docker compose up -d

모두 같은 Docker 설정을 쓰면 "내 PC에선 되는데"가 안 생겨요. docker-compose.yml은 ①이 관리합니다.

DAILY · 매일 작업 흐름

# ① 작업 시작 전: 최신 main 받기
git switch main
git pull

# ② 내 작업 브랜치 만들기 (작업 하나당 브랜치 하나)
git switch -c feature/sql-analysis-queries

# ③ 작업하고, 내가 바꾼 파일만 골라서 커밋
git status
git add sql/analysis_queries.sql
git commit -m "sql: 서버별 패치 완료율 쿼리 추가"

# ④ GitHub에 올리기
git push -u origin feature/sql-analysis-queries

# ⑤ GitHub 웹에서 "Compare & pull request" → PR 만들기
#    → 다른 한 명이 확인하고 Merge

# ⑥ 합쳐지면 main으로 돌아가서 다시 ①부터
git switch main
git pull

RULES · 같이 쓰는 규칙

브랜치 이름

feature/역할-작업명 형식으로 지어요.

①feature/db-trigger
②feature/sql-performance
③feature/app-search
④feature/data-collect
버그fix/app-status-update

커밋 메시지

영역: 무엇을 했는지 한 줄이면 충분해요.

  • db: patch_history 자동 기록 트리거 추가
  • sql: 기한 초과 미해결 건 쿼리 추가
  • app: 패치 상태 변경 화면
  • data: NVD 수집 스크립트
  • docs: 데이터 매핑 문서

PR 규칙

  • main에 직접 push하지 않고 항상 PR로 합치기
  • PR 설명에 무엇을 바꿨는지, 어떻게 확인했는지 2~3줄
  • 다른 한 명이 확인하고 Merge (급하면 단톡에 말하고 본인 Merge)
  • PR은 작게. 하루 작업을 하루 안에 합치기
  • db/schema.sql을 건드리는 PR은 반드시 ①이 확인

하지 말 것

  • git add . — 다른 파일까지 같이 올라가요
  • git push --force — 다른 사람 작업이 날아가요
  • .env, 비밀번호, API 키 커밋
  • 남의 폴더 파일 마음대로 수정 (필요하면 담당자에게 말하기)
  • 며칠씩 PR 안 하고 혼자 쌓아 두기 (나중에 충돌 지옥)

CONFLICT · 충돌이 났을 때

main의 최신 내용을 내 브랜치에 반영

git switch main
git pull
git switch feature/내-브랜치
git merge main

충돌 난 파일을 열면 <<<<<<< ~ >>>>>>> 사이에 두 버전이 보여요. 남길 내용만 남기고 표시를 지운 뒤:

git add 충돌난파일
git commit
git push

모르겠으면 멈추고 공유

충돌이 다른 사람 파일에서 났거나, 뭘 남겨야 할지 모르겠으면 아무것도 지우지 말고 단톡에 git status 결과를 캡처해서 올려 주세요.

Git은 커밋만 해 두면 거의 다 되돌릴 수 있어요. 무서운 건 커밋 안 한 작업을 날리는 거예요.

VS Code를 쓰면 충돌 부분에 "Accept Current / Incoming / Both" 버튼이 떠서 훨씬 쉬워요.

AI TOOLS · Claude Code·Copilot 등을 쓸 때

  • 내 담당 폴더 밖의 파일, 특히 db/schema.sql을 마음대로 고치지 않았는지
  • CVE 번호·CVSS·수정 버전을 지어내지 않았는지 (실제 데이터는 출처가 있어야 해요)
  • git add .나 main 직접 push를 하지 않았는지

LEADER · 팀장이 한 번 해 둘 세팅
