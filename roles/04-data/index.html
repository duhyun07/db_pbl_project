NOTE · 참고

CVE 고르는 기준

  • Ubuntu 24.04(noble)에서 상태가 released인 Apache·OpenSSH CVE 위주
  • 24.04 출시 전에 고쳐진 CVE는 not-affected로 나와서 시연에 쓸모가 없어요
  • CVSS 점수 분포가 고르게 (높음·중간·낮음 + 점수 없는 것 1~2개)
  • 모든 값은 출처 URL과 함께 기록

시연용 가상 데이터에 꼭 넣을 경우

  • 기한을 넘긴 미해결 건
  • 완료율 0%인 서버, 100%인 서버
  • 같은 CVE가 여러 서버에 있는 경우
  • 담당자가 아직 없는 건
  • 상태가 여러 번 바뀐 이력이 있는 건

CAUTION · 주의할 점

  • Ubuntu JSON의 noble은 DB에 24.04로 변환해서 넣어요. ubuntu_release에는 CHECK 제약(^[0-9]{2}[.][0-9]{2}$)이 있어서 코드명을 그대로 넣으면 오류 3819가 나요. (jammy → 22.04)
  • CVSS나 수정 버전이 없으면 지어내지 말고 NULL. 원본 JSON을 남겨 둬야 나중에 근거를 보여줄 수 있어요.
  • NVD API는 API 키 없이 쓰면 요청 횟수 제한이 빡빡해요. 요청 사이에 간격(sleep)을 두세요.
  • 서버에 설치되는 건 바이너리 패키지(openssh-server), CVE 상태는 소스 패키지(openssh) 기준이에요. 이 매핑을 꼭 처리하세요.
  • 영향 여부는 버전 문자열 비교가 아니라 python-debian의 Version 비교로 판정하세요 (Ubuntu 백포트 때문).
  • 가상 데이터는 random seed를 고정해서 누가 돌려도 같은 데이터가 나오게 하기.
